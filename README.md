# Train_control

Nゲージ路面電車向けの進路選択シミュレーター。実機・GPIO出力はありません。

## 起動

### Windowsで開く

1. Python 3を https://www.python.org/downloads/windows/ からインストールします（Python Launcherもインストール）。
2. GitHubの「Code」→「Download ZIP」でダウンロードし、ZIPを右クリックして「すべて展開」します。
3. 展開先の `start-windows.bat` をダブルクリックします。
4. 黒い画面を開いたまま、EdgeやChromeで `http://localhost:8000` を開きます。
5. 終了するときは黒い画面で Ctrl+C を押します。

`index.html` のダブルクリックではJavaScriptのモジュールが読み込まれないため、必ずサーバー経由で開いてください。

### 開発環境

Python 3とNode.js（テスト用）を使用します。外部パッケージの導入は不要です。

```sh
cd /workspace/Train_control
npm test
npm start
```

ブラウザでサーバーの8000番ポートにアクセスします。クラウド環境では公開方法が別途必要です。

## 操作

- 上側1の外側・内側：時間差方式。A→Bが設定境界未満なら直進、以上なら分岐。
- 下側2の外側・内側：LED方式。A検知から直・曲を交互表示し、B検知時の表示で決定。
- 各組の「センサA 通過」「センサB 通過」を順に押します。
- 決定後はポイントを模擬的に切り替え、進路をロックします。「通過完了」で待機へ戻します。
- 両方式とも、A検知やLEDの交互表示ではポイントを操作しません。Bで進路を確定した時点だけ位置を更新します。通過完了後も前回位置を保持します。起動直後の位置は「未確認」です。
- 設定変更は4組とも待機中の場合のみ可能です。再読み込みで状態と設定を初期化します。

図のセンサ・ポイント位置は仮配置です。交差部での線路接続はありません。
列車の速度・停止・発車は運転者が操作します。信号は進路決定の模擬表示のみで、在線・競合進路の連動は未実装です。

## 実機化の前に

ポイント駆動と車両非加工の光センサについて、[実機回路の設計案](hardware/README.md)を参照してください。未確認の電気仕様があり、まだ通電用の確定回路ではありません。

Raspberry Pi 4 Model B、KATO 40-231を基準に設計しています。
[センサとPiの配線・取付設計](hardware/sensor-design.md)、[機種・8入力の設定例](config/pi4.example.json)を追加しました。
センサの検知フィルタは単体テスト済みですが、SPI読み取り・校正画面・既存操作盤への接続はまだありません。
センサ型番と実測による校正、ポイント駆動条件、信号の仕様は今後確定します。
ポイント切替完了の確認、列車通過・在線検知、競合進路の排他、入力のチャタリング対策を追加してから実機出力を実装します。
GPIOにポイントの駆動負荷を直接接続しないでください。

ポイントの12V試作回路と部品表・試験手順は[駆動回路設計](hardware/turnout-driver.md)を参照してください。設定例の出力は無効のままで、実機GPIO制御は未実装です。

JLCPCB向けの[試作基板データ・実装依頼準備](hardware/pcb/README.md)を追加しました。
100×100mm・2層の3.3V制御基板で、8センサ入力と4系統のパルス制御を搭載します。
DRV8871と12V負荷回路は別置きです。信号灯の駆動回路は今回の基板に含みません。
DRC/ERCと回路図・基板の接続一致を確認済みですが、実機動作は未検証です。

最新のRev Cでは、4系統それぞれにパルス幅調整用の多回転トリマVRを追加しました。
目安は約50〜80msで、100ms以下になることを実機接続前に測定する必要があります。発注ZIP・PDFは`TC_IO_REVC`版を使用してください。

部品実装込みへ方針を変更しています。[PCBA用BOM/CPL草案と未確定事項](hardware/pcb/pcba/README.md)を確認してください。
現行はVRを含め表面実装50点の候補回路です。コネクタ部品を使わず、電線直結用の穴を残します。JLCPCBでの実装対応・部品番号・在庫・CPLの位置と回転が未確認のため、実装注文に使える確定セットではありません。
