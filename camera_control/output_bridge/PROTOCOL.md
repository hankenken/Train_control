# TC2 USBシリアル仕様案 — DRV8235 I2Cブリッジ

**提案仕様であり、ホストクライアント・ファームウェアは未実装です。実機へ送って動作するコマンド表ではありません。** 旧TC1/GPIO→DRV8871案とは別の識別子を使います。
WindowsとLattePanda内蔵ATmega32U4のUSBシリアルを想定し、MCUがDRV8235×4をI2Cで制御します。追加のI2C変換器をWindowsから直接操作する方式ではありません。

## フレームと識別

ASCII、LF終端、任意の終端CRを許容。1行63バイト以内を想定します。ボーレート指定は115200ですが、内部USB CDCの実転送速度を保証する値ではありません。
起動直後はDISARMED、nSLEEP禁止、全ドライバOFFを確認する状態から始めます。USB接続待ちで通電管理をブロックしません。

```text
HELLO
READY TC2 DRV8235_I2C
```

HELLOはプロトコル識別だけです。ARM・出力・故障解除・シーケンスリセットは行いません。
異なる識別子や不明な応答を受け取ったホストは、実機出力を要求しません。

## コマンド案

`seq`は1〜4294967295の十進整数。MCU起動中は単調増加とし、同じ番号のPULSEを再実行しません。

| コマンド | 条件・意味 | 成功応答 |
|---|---|---|
| `STATUS` | 状態参照のみ。seqなし、出力や時刻を更新しない | 下記STATUS行 |
| `HB <seq>` | ホスト生存確認時刻を更新。ARMやパルスを開始しない | `OK <seq> HB` |
| `ARM <seq>` | 新鮮なHB、非駆動、全ドライバ設定確認、故障なしで明示許可 | `OK <seq> ARM` |
| `PULSE <seq> <ch> <P\|N> <ms>` | 許可済みで1系統へ単発要求。ch=0〜3、初期範囲20〜100ms | `OK <seq> PULSE` |
| `STOP <seq>` | 出力禁止・単発取消し・DISARM。I2C停止失敗時もnSLEEP禁止を使う | `OK <seq> STOP` |

STATUSの形式案：

```text
STATUS TC2 DRV8235_I2C armed=0 active=-1 last_seq=0 hb_age_ms=-1 fault=NONE
```

`active`は非駆動なら-1、駆動中なら0〜3。`hb_age_ms=-1`は未受信。`last_seq`でホストが再接続後に古い番号を送らないようにします。
再接続だけで故障を解除したり、自動でARMしたりしません。

## パルスの意味

| ch | DRV8235の7ビットアドレス | 線区 |
|---:|---|---|
| 0 | 0x30 | upper_outer |
| 1 | 0x32 | upper_inner |
| 2 | 0x36 | lower_outer |
| 3 | 0x38 | lower_inner |

PはI2C駆動ビット10（OUT1→OUT2）、Nは01（逆極性）。青白と直進／分岐の対応は実機で確認して別設定に記録します。
`OK ... PULSE`は要求を受理した意味で、ポイント転換の成功確認ではありません。
正常な単発終了でI2CのOFF・EN_OUT解除を確認した後の通知案：

```text
DONE <seq> <ch>
```

DONEも物理位置や最後尾通過の確認ではありません。エラーで途中取消しの場合に、正常終了のDONEを返しません。
I2CフレームのSTOP条件と、このプロトコルのSTOPコマンドは別です。通常OFFにはドライバレジスタの操作が必要です。

## 拒否・時間・異常時の方針

- 同時パルスは最大1系統。駆動中に届いた正しい別PULSEは`ERR <seq> BUSY`で拒否し、既存の単発を延長しない。
- 各系統の再駆動は前回OFFから1秒以上を初期条件とし、早い要求は`ERR <seq> COOLDOWN`で拒否。メーカー保証の冷却時間ではない。
- ホストHB間隔は100msを初期案、期限500ms。期限切れでDISARM・nSLEEP禁止。厳密な100ms以下を保証する時間制限ではない。
- 正しい構文と新しいseqのHB/ARM/PULSE/STOPは、BUSY・COOLDOWN・DISARMED等で拒否されてもseqを消費する案。
- 古い／重複seqは`ERR <seq> STALE`で拒否し、再通電しない。STOPだけは古いseqでも禁止動作を優先し、その後STALEを返す案。
- 不正構文、値範囲外、バッファ超過、USB切断、I2C失敗、読戻し不一致は保守的にDISARM。長すぎる行は改行まで破棄し、残りを別コマンドとして解釈しない。
- seqを信頼できない不正行は`ERR 0 MALFORMED`、超過行は`ERR 0 LINE_TOO_LONG`を想定。
- エラー理由案は`DISARMED`、`HEARTBEAT_TIMEOUT`、`BUSY`、`COOLDOWN`、`STALE`、`I2C_FAULT`、`CONFIG_MISMATCH`等。最終実装時に固定し、ホストと機器で一致させる。
- 応答が失われても、ホストはPULSEを自動再送しない。既に駆動開始している可能性があるため、新しいseqでSTOPを試み、故障状態として接続を終了する方針。
- 時間管理は`millis()`等の符号なし差分を使い、オーバーフローを考慮する。駆動終了を`delay()`やブロッキングUSB/I2C待ちに依存させない。

## 初期化と故障からの復旧

通常の初期化は、VM電源投入の安全な初期状態から開始し、EN_OUT=0を維持したままPMODE・I2C_BC・電流制限・ストール無効・保護モードを設定、全4個の読戻しを確認します。
新鮮なHBと明示的ARMの後、必要な系統だけを駆動します。ホスト接続やHELLOだけで駆動を許可しません。

TI資料31ページ§7.3.7.4は、スリープ中の内部デジタルロジックリセットとEN_OVP状態のラッチを記載しています。**故障後の自動ARMは行いません**。ウェイク待ち後に全4個のEN_OUT=0を確認し、必要な設定の再初期化・読戻し・明示的ARMを行う方針です。
OVPはスリープ／High-Z中の逆起電力条件で下側FETをONにする場合があるため、停止時の電流と回生も別途実機で評価します。

現段階ではコードも実機試験結果もありません。この仕様を、100msのハードウェア上限保証・電気的安全性・転換成功の証明として使用しないでください。
