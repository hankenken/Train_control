# 通信対応ポイントドライバ — DRV8235採用候補

**カメラでの認識と画面上の模擬制御を先行し、この通信試作は保留中です。** 独立したファームウェア・Python試験クライアントの初稿があり、クラウド上のコンパイル・模擬試験までで実機未検証です。PCカメラ検証ZIPにはこれらの実出力用コードを含めません。 カメラアプリは引き続き`outputs_enabled:false`で、ポイントやGPIOを操作しません。

ユーザー指定の「ドライバIC自体が通信に対応」に合わせ、旧案のGPIO入力専用DRV8871から、**I2CでHブリッジを直接制御できるTI DRV8235**へ選定を変更します。旧DRV8871の基板・資料は履歴であり、この通信方式の採用品として扱いません。購入・基板発注用に確定した部品コードやガーバーはまだありません。

## 構成案と費用の考え方

```text
LattePanda 3 Delta 864 / Windows 10
  カメラ進路判定（現在は模擬出力のみ）
        ↓ 本体内のUSBシリアル／COM（独立試作・カメラ未接続）
  内蔵ATmega32U4
        ↓ I2C（SDA/SCL/GND）
  DRV8235 ×4 → ポイント青・白線 ×4組
        ↑ 共通nSLEEPによる出力禁止・電源保護（回路草案・未製作）
```

追加のUSB-I2C変換器や外付けマイコンを購入せず、LattePanda内蔵マイコンを利用する案です。WindowsがI2C端子を直接操作する構成ではありません。
ポイントの方向・駆動／OFFは**DRV8235のI2Cレジスタ**で選びます。nSLEEPの別配線は故障時の禁止手段であり、通常の方向制御をGPIOで代用するものではありません。

DRV8235は3×3mmの16端子WQFN・露出パッド付きで、手配線用DIPではありません。4個を1枚の小型基板へ実装する方向で検討し、基板実装費・保護部品・配線を含む見積もりが必要です。「変換器を省ける」ことと、実装込みで最安であることは別です。現時点の単価・在庫は確認していません。

根拠：TI **SLVSHO3、April 2024**。公式URL：<https://www.ti.com/lit/ds/symlink/drv8235.pdf>

| 項目 | 確認内容 | 本文ページ |

| 電源 | VM動作範囲4.5〜38V。今回のポイント用は12Vを初期条件とする | 1、5 |
| 出力 | 1個につき1つの極性反転Hブリッジ。3.7Aはピーク仕様で、連続・基板放熱を保証する値ではない | 1 |
| I2C駆動 | `I2C_BC=1`で内部レジスタの入力ビットがHブリッジを制御 | 13〜14、51 |
| 電源投入時 | `CONFIG0.EN_OUT`のリセット値は0。全FETがHigh-Z | 47 |

| ウェイク | nSLEEPをHIGHにしてからI2C準備まで最大410µs | 6 |

### 4個のアドレス（7ビット）

Arduino `Wire`などへ渡すのは右欄の**7ビット値**です。資料のWRITE/READ欄にはR/Wビットを含む8ビット値が掲載されています。

| ポイント系統 | A1 | A0 | 資料のWRITE値 | 使用する7ビット値 |
|---|---|---|---|---|
| 0 / upper_outer | GND | GND | 0x60 | **0x30** |
| 1 / upper_inner | GND | ロジックHIGH | 0x64 | **0x32** |
| 2 / lower_outer | ロジックHIGH | GND | 0x6C | **0x36** |
| 3 / lower_inner | ロジックHIGH | ロジックHIGH | 0x70 | **0x38** |

4個ともGND/HIGHの固定設定を使い、浮遊のHi-Zアドレス状態を使わない案です。I2Cマルチプレクサは不要です。アドレスは運転中に切り替えません。
同じバスに付く他デバイスとの競合、実際の配線・立上り時間は確認が必要です。

### 通信での方向・OFF

`CONFIG4`はアドレス`0x0D`。`PMODE`（bit3）を1、`I2C_BC`（bit2）を1にし、bit1/bit0で制御します。

| bit1 / bit0 | OUT1 / OUT2 | 意味 |
|---|---|---|
| 0 / 0 | High-Z / High-Z | 通常OFF（Coast） |
| 1 / 0 | HIGH / LOW | 極性P |
| 0 / 1 | LOW / HIGH | 極性N |
| 1 / 1 | LOW / LOW | Brake。通常のポイント要求では使用しない |

さらに`CONFIG0`（`0x09`）のbit7 `EN_OUT=0`で全FETをHigh-Zにします。方向の設定・読戻し確認後に必要な系統だけ有効化する手順を設計します。
**I2CのSTOP条件は通信フレームの終端であり、コイル通電を停止する命令ではありません。** 必ずOFFビット／EN_OUTを変更する必要があります。

回転モータ用のストール検出は初期値で有効です。ポイントのソレノイドにそのまま適用せず、`EN_STALL=0`を明示する案です。OCP/TSDの自動リトライも、ポイントへ自動再通電しないようラッチ停止方式を選ぶ方向で検討します。

## 電流制限と5Vロジックの注意

電流制限はIPROPIの抵抗とVREFで設定します（本文17ページの式）。

```text
Itrip = VREF / (1500 µA/A × RIPROPI)
```

内部3V基準を使用する場合、公称1.2A相当の抵抗は約1.67kΩです。これは式の試算で、採用抵抗・許容差・電流鏡誤差込みの確定値ではありません。現在の53.6kΩ（旧DRV8871用）を流用しません。
`IMODE`等も初期値任せにせず、駆動中の電流制限が有効になる設定を確認します。

**外部VREFの最大推奨値は3.3Vです。ロジックが5V対応でも、VREFへ5Vを入れてはいけません。** 内部3V基準の使用条件、VREFピンの外部処理は回路設計時に資料と照合します。

## マイコン側の端子とバス

Arduino公式Leonardoのピン図で、ATmega32U4のArduino論理ピン **D2=SDA、D3=SCL** を確認しました。資料：<https://docs.arduino.cc/resources/pinouts/A000057-full-pinout.pdf>
LattePandaの実際の引出し端子・シルク印刷は本体の公式ピン図と現物で再確認します。Arduinoの論理番号をRaspberry Piの40ピン物理番号として配線しません。

初期バス速度は100kHzを候補とし、短い共通SDA/SCL/GNDで4個へ接続します。5VプルアップはDRV8235のロジック範囲内ですが、他のI2Cデバイスが同居する場合はその電圧範囲も確認します。
バスのプルアップは共有の1組で評価し、各モジュールの抵抗を無条件に並列へ増やしません。例えば2.2kΩが4組並列だと550Ωとなり、必要な吸込み電流が増えます。

## 通電時間・通信途絶時の禁止

DRV8235の資料から、I2C更新が途絶えると自動的に20〜100msでOFFになるウォッチドッグ／ワンショットは確認できませんでした。通信で書いた駆動状態は、通信終了だけでは解除されない前提で設計します。

- MCU側で単発時間を管理し、通常終了はOFF=00、EN_OUT=0の書込み・読戻しを行う。
- USB切断、ハートビート期限切れ、I2C失敗、設定不一致では、I2C書込みに依存せず共通nSLEEPをLOWにして禁止する。
- nSLEEPには外部プルダウンを設け、MCUリセット・未給電時も禁止側を意図する。
- MCUウォッチドッグは補助。MCU停止から再起動までの時間や出力浮遊を含むため、**厳密な100ms以内の独立したハードウェア保証にはならない**。
- コイルの温度・電流・繰返し、保持型停止スイッチ、12V保護・回生、起動順序は実機で試験する。

資料31ページ§7.3.7.4には、スリープ中に内部デジタルロジックがリセットされる一方、EN_OVPの状態はラッチされると記載されています。前回の設定を保持する前提で再利用せず、**故障後の自動再ARMは行いません**。ウェイク待ち後に全4個のEN_OUT=0と必要な初期値を確認し、再設定・読戻しを完了してから明示的なARMを行う方針です。
同節では、スリープ／High-Z中も出力がVMより約200mV高くなる条件でOVPが下側FETをONにし、逆起電力をブレーキする動作が記載されています。したがって「スリープなら常に全FETがOFF」とは扱わず、ソレノイドの回生・クランプ・停止条件を含めて評価します。
