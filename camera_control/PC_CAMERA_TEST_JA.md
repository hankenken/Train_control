# USBカメラで車両認識と模擬制御を試す

**まずはPC・USBカメラ1台・模型1編成で確認します。ポイント回路、I²C配線、Arduino書込みは不要です。** カメラは実映像を使い、制御出力は画面だけに表示します。LattePanda 3 Delta 864のWindows10、または検証用のWindows10 x64 PCを想定しています。

## 初回だけ行う準備

1. Windows用Python 3.12 **64-bit**を https://www.python.org/downloads/windows/ からインストールします。Python Launcherも導入します。
2. ZIPを右クリックして「すべて展開」。`camera_control`フォルダが見える場所でPowerShellを開き、次を実行します。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\camera_control\scripts\setup_windows.ps1
```

必要なソフトは展開フォルダ内の`.venv-camera`へ導入されます。管理者権限や、恒久的な実行ポリシー変更は不要です。シリアル通信部品やファームウェアは導入しません。

USBカメラをPCへ接続します。Windowsの「設定 → プライバシー → カメラ」でデスクトップアプリのカメラ利用を許可し、カメラを使っている別アプリを閉じます。最初は線路全体を写そうとせず、**直線の短い1区間と1編成が十分大きく写る位置**で固定します。照明・ピントが変わりにくい場所で試します。

## 起動する

`camera_control`内の **`START_CAMERA_TEST.cmd`をダブルクリック**します。黒い画面でカメラ番号の **0** を押します。別のカメラが映った場合はCtrl+Cで終了して起動し直し、1、2、3を順に試します。USB差し替えで番号が変わる場合があります。

黒い画面を開いたまま、ChromeまたはEdgeで **http://127.0.0.1:8000** を開きます。終了するときは黒い画面でCtrl+Cです。

以前の画面が表示される場合は、以前のサーバーの黒い画面をCtrl+Cで終了してから起動し直し、ブラウザをCtrl+F5で更新します。

初期要求は640×480・15fps・MJPGです。実際の受信サイズが異なる場合は画面にエラーが出ます。カメラの対応モードに合わせ、PowerShellから次のように変更できます。

```powershell
.\.venv-camera\Scripts\python.exe -m camera_control.camera_test --device 0 --capture-size 1280 720 --fourcc MJPG
```

640×480でMJPGに対応していない場合は`--fourcc YUY2`、DirectShowで取得できない場合は`--backend msmf`を指定します。サイズ・形式が合っているかはカメラの対応モードで確認してください。内蔵カメラと外付けカメラは番号だけで区別せず、映像で確認します。

## 画面上で設定する

1. 映像の下の **「検出範囲・A/Bを設定」** を押します。設定用の静止画像が開きます。
2. 線路1本の短い直線区間を囲む長方形の、対角の角を2回クリックします。隣の線路や手が入りにくく、車体全体の幅が入る範囲にします。
3. 範囲内の **A位置、B位置** を順にクリックします。A→Bが進行方向になります。A・Bの線は自動で描画されます。
4. 方式を選びます。「時間差」はA→Bが設定秒数未満なら直、以上なら曲。「LED」はAから直・曲を交互表示し、Bを通過したときの表示で決まります。
5. **「適用して背景登録へ」** を押します。この時点ではまだ車両認識を開始しません。
6. 映像の範囲から車両と手をすべて取り除き、確認チェックを入れ、**「空の背景を登録」** を押します。

位置設定では車両が写っていても構いませんが、背景登録は車両がない状態で行います。カメラを動かした、照明・露出・ピント・解像度を変えた場合は、位置と背景を登録し直します。

## 認識と模擬出力を確認する

1. 車両をAより手前に置き、手を映像から離します。**緑の枠とID、面積**が表示されることを確認します。停止中も枠が残る方式です。
2. 手動でA→Bへ走らせます。Aで「Bの判定待ち」になり、**ポイント（模擬）の位置は変わりません**。
3. Bで「進路確定・ロック中」となり、模擬ポイントの直／曲の線と「模擬出力 #…」が更新されることを確認します。A→Bの時間も表示します。
4. 編成全体を検出区間から出します。「編成全体が通過したことを確認」にチェックし、**「通過完了・ロック解除」** を押します。前回の模擬ポイント位置は保持されます。
5. 時間や方式を変える場合は、待機状態で再度範囲設定を行い、背景も登録し直します。まず時間差で速い／遅い通過、その後LED方式で異なるタイミングの通過を試します。

枠が出ない場合は設定画面の最小面積を下げます。ノイズが多い場合は最小面積か背景差のしきい値を上げます。表示される面積の画素数を参考に調整し、適用後は空の背景を再登録してください。

識別が不確かな場合は赤表示・判定保留になり、進路を推測して切り替えません。確認後に解除して再試験します。A待ち状態を取り消す場合は「検出を一時停止」を押し、車両の通過確認・ロック解除後に検出を再開します。

## 次回用に保存する

ページ下部「設定の確認・保存」を開き、**「設定を保存（JSON）」** を押します。ダウンロードした`camera-test.local.json`を、`START_CAMERA_TEST.cmd`と同じ`camera_control`フォルダへ置きます。次回はこの設定を読み込みます。**背景画像は保存しないため、起動ごとに空の背景を登録します。**

最初から設定し直す場合は、`camera-test.local.json`のファイル名を別名に変えてから起動します。設定ファイルの内容がカメラと合わない場合も、画面エラーを確認して設定し直してください。

## 何を検証できるか

- 空背景との差による車両候補の検出、停止中の認識、IDの連続性。
- 仮想A/Bの通過、時間差・LED位相による進路選択。
- Bより前に模擬出力が変わらないこと、通過完了でも前回位置が保持されること。

車種を学習済みAIで判別する方式ではなく、手・影・揺れる架線・照明変動にも反応します。車両の塗色による個体識別、カメラ間のID引継ぎ、編成全体の自動判定は未実装です。カメラ画像の時刻はPCでの読取り完了時刻なので、USB内部遅延を含む実際のB通過時刻との差も今後測定します。

**この試験で実物のポイント・信号・列車電源は操作されません。** COMポートも開きません。実カメラ・模型による認識精度と、Windows実機上の処理速度はまだ未測定です。
