# LattePanda・Windows10・通信対応ドライバ構成

- 映像：USB UVC×2 → OpenCV（DirectShow、必要ならMSMF） → 空背景と線路ROIによる検出。
- 判断：A/B通過、時間差／交互表示の2方式。運転・停止・発車は手動。
- 表示：本体上のFastAPIとブラウザ。PCを追加しない。
- 将来の出力：Windows → 内蔵USBシリアル → 内蔵ATmega32U4 → I2C → DRV8235×4 → ポイント。
- ドライバICは実際にI2C対応。アドレスは7bitで0x30、0x32、0x36、0x38。
- ソフトは現段階で実出力を実装しない。COMを開く処理・ファームウェア・新しい駆動基板は未作成。

## カメラ時刻と遅延

USBの時刻はOpenCVで読取りが完了したホスト時刻で、露光時刻ではない。
最新1枚だけを保持する処理でアプリ内の滞留を防ぐが、USB／Windowsドライバ内の遅延までは解消・測定できない。
タイミング方式のLED位相と、実車のB通過時刻のずれは実機で測定する。A/Bは同じカメラが担当する。
カメラ番号は再接続で変わる場合があるため、毎回映像で担当範囲を確認する。

## 費用の方針

本体RAM/eMMC、内蔵MCU、手持ち画面・入力機器・適合電源を優先利用。
追加USB-I2C変換器・ラズパイ・AIアクセラレータ・SSD・USBハブを初期の必須品にしない。
USBカメラの画角、モード、価格・在庫が合う具体型番は未確定。予算目標を見積価格として扱わない。
DRV8235は3mm角WQFNで、小型化には有利だが実装基板が必要。4系統を一枚へ集約して部品数・通信回路を抑える方向で検討する。
ポイント用12V電源・保護・パルス制限は省略しない。

Windows10／LattePanda実機の導入、2カメラの速度・画角・遅延、実車の追跡、実装部品のLCSC調達、I2C設定・出力パルスと故障時の波形は未確認。
